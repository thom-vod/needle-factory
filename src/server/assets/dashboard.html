Getting Started


            
What is needle

            
Needle is a DOT-graph pipeline runner. You define workflows as Graphviz DOT files where nodes represent pipeline stages (LLM calls, shell commands, human approvals, parallel branches) and edges represent control flow. Needle executes the graph, handles retries and checkpoints, and streams events to a real-time web dashboard.


            
Quick Setup

            
# Build
mkdir build && cd build
cmake .. -DNEEDLE_BUILD_SERVER=ON
make -j$(nproc)

# Run with an existing pipeline
./needle serve sample_dots/simple_pipeline.dot

# Or start with an empty workspace
./needle serve

            
Then open http://localhost:8080 in your browser.

Pipeline Syntax


            
DOT Format Basics

            
Pipelines are standard Graphviz digraph definitions. Each pipeline must have exactly one start node (shape=Mdiamond) and one exit node (shape=Msquare).

            
digraph my_pipeline {
    graph [goal="Build and test the project", label="CI Pipeline"]

    start [shape=Mdiamond, label="Start"]
    build [label="Build", handler="tool", command="make"]
    exit  [shape=Msquare, label="Done"]

    start -> build -> exit
}


            
Graph Attributes

            

              
AttributeDescription

              
                
goalHigh-level goal for the pipeline. Accessible as $goal in prompts.

                
labelDisplay name shown in the dashboard.

                
templateSet to "true" to mark this graph as a template.

                
paramsTemplate parameter definitions (see Template System).

              
            


            
Node Attributes

            

              
AttributeDescription

              
                
labelDisplay name for the node.

                
handlerHandler type: codergen, tool, interactive, llmkit, etc. Inferred from shape or type if not set.

                
typeAlias for handler (legacy). Use handler for clarity.

                
shapeGraphviz shape. Special shapes: Mdiamond (start), Msquare (exit), component (parallel), trapezium (fan_in), hexagon (wait_human).

                
promptPrompt text for LLM-based handlers (codergen, llmkit, interactive).

                
commandShell command for tool nodes.

                
agentCLI agent: "claude", "codex", or "gemini". (Alias: llm_provider)

                
llm_modelModel name override.

                
modeExecution mode for interactive nodes: "interactive" or "autonomous".

                
max_iterationsMax loop count for manager_loop nodes.

                
goal_gateSet to "true" for manager_loop exit condition.

                
join_policyHow parallel results are merged: "consensus", "first", etc.

                
dot_filePath to sub-pipeline DOT file for nested_run nodes.

              
            


            
Edge Attributes

            

              
AttributeDescription

              
                
labelDisplay label on the edge.

                
conditionCondition expression for branching, e.g., outcome=success or outcome!=success.

              
            


            
Variable Syntax

            
Prompts and attributes support variable expansion:

            

              
SyntaxDescription

              
                
$var.nameTemplate parameter or --var CLI value.

                
$context.handler.node.fieldOutput from a previous node, e.g., $context.codergen.build.output.

                
$goalThe graph-level goal attribute.

              
            


            
Example Pipeline

            
digraph ci_pipeline {
    graph [goal="Build, test, and deploy", label="CI Pipeline"]

    start      [shape=Mdiamond, label="Start"]
    build      [handler="tool", label="Build", command="make"]
    test_unit  [handler="tool", label="Unit Tests", command="make test"]
    test_lint  [handler="tool", label="Lint", command="make lint"]
    merge      [shape=trapezium, label="Merge Results"]
    review     [shape=hexagon, label="Review"]
    deploy     [handler="tool", label="Deploy", command="make deploy"]
    exit       [shape=Msquare, label="Done"]

    start -> build
    build -> test_unit
    build -> test_lint
    test_unit -> merge
    test_lint -> merge
    merge -> review
    review -> deploy [label="Approve"]
    deploy -> exit
}

          


          
          

            
Node Types & Handlers

            
Each node in a pipeline has a handler that determines how it executes. The handler is set via the handler attribute, or inferred from the shape or type attribute.


            
start

            
Entry point for the pipeline. Exactly one required per graph.

            
start [shape=Mdiamond, label="Start"]


            
exit

            
Termination point. Exactly one required per graph.

            
exit [shape=Msquare, label="Done"]


            
codergen

            
Runs an external CLI code-generation tool (e.g., Claude Code, Codex). The prompt attribute provides instructions. This is the default handler for nodes without a special shape.

            
implement [label="Implement Feature", prompt="Build the HTTP server with REST endpoints..."]


            
llmkit

            
Calls an LLM provider directly via API (no CLI tool). Use llm_provider and llm_model to configure.

            
analyze [handler="llmkit", label="Analyze", llm_provider="anthropic",
    llm_model="claude-sonnet-4-6", prompt="Analyze the test results..."]


            
tool

            
Executes a shell command. The command attribute specifies what to run. The exit code determines success/failure.

            
build [handler="tool", label="Build", command="make -j$(nproc)"]
test  [handler="tool", label="Test", command="make test"]


            
interactive

            
Human-AI collaborative chat session. When mode="interactive", the dashboard shows a chat panel. When mode="autonomous", the AI runs without human input.

            
ideate [handler="interactive", label="Ideate", mode="$var.ideation_mode",
    prompt="Help the user develop their project idea..."]


            
wait_human

            
Pauses the pipeline for human approval or input. Displays a modal in the dashboard with choices. Use shape=hexagon for automatic inference.

            
review [shape=hexagon, label="Review & Approve",
    prompt="Review the implementation and decide whether to proceed."]


            
parallel / fan_in

            
Parallel fans out to execute all outgoing edges concurrently. Fan-in is the synchronization point that waits for all parallel branches to complete.

            
fan_out [shape=component, label="Run Tests", join_policy="consensus"]
test_a  [label="Test Suite A", prompt="Run the A tests..."]
test_b  [label="Test Suite B", prompt="Run the B tests..."]
fan_in  [shape=trapezium, label="Merge Results"]

fan_out -> test_a -> fan_in
fan_out -> test_b -> fan_in

            
The join_policy attribute on the parallel node controls how results are merged: "consensus" produces a merged summary, "first" takes the first result.


            
manager_loop

            
Iterative loop that re-executes a subgraph until a goal condition is met or max_iterations is reached.

            
loop [handler="manager_loop", label="Fix Loop", max_iterations="5"]


            
doc_fetch

            
Fetches and processes external documents or repositories. Useful for pulling reference material into the pipeline context.

            
fetch_refs [handler="doc_fetch", label="Fetch References",
    prompt="Clone and analyze relevant open-source projects..."]


            
web_search

            
Performs web search using the Tavily API. Requires a TAVILY_API_KEY environment variable.

            
search [handler="web_search", label="Search Web",
    query="latest best practices for distributed systems"]


            
nested_run

            
Executes another DOT pipeline as a sub-pipeline. The dot_file attribute specifies the path to the sub-pipeline.

            
execute [handler="nested_run", label="Run Implementation",
    dot_file="project.dot", timeout="60m"]


            
conditional

            
Branches based on edge conditions. Outgoing edges use condition attributes to determine which path is taken.

            
check [handler="conditional", label="Check Results"]

check -> deploy [label="pass", condition="outcome=success"]
check -> fix    [label="fail", condition="outcome!=success"]

          


          
          

            
Template System


            
What are Templates

            
Templates are reusable pipeline definitions with parameterized values. They are regular DOT files with template="true" set on the graph and a params attribute that defines user-configurable parameters. When loaded, the dashboard prompts the user to fill in the parameters before running.


            
Template Params Syntax

            
The params graph attribute defines parameters as a comma-separated list:

            
graph [template="true", params="name:type:default, ..."]

            
Each parameter has the format:

            
param_name:param_type:default_value

            

              
TypeDescriptionExample

              
                
textFree-form text inputseed:text:required

                
choice(...)Dropdown selection from optionsmode:choice(interactive|autonomous):interactive

              
            

            
Use required as the default to make a parameter mandatory. Use optional to allow it to be left empty.


            
Variable Expansion

            
Template parameters are accessed in prompts and attributes using $var.param_name:

            
ideate [handler="interactive", mode="$var.ideation_mode",
    prompt="Help refine the idea: $var.seed"]

            
Variables are expanded at runtime before the node executes.


            
Creating Custom Templates

            
    
              
  1. Write a standard pipeline DOT file.
    2. 
              
  2. Add template="true" to the graph attributes.
    3. 
              
  3. Define parameters in the params attribute.
    4. 
              
  4. Replace hardcoded values with $var.param_name references.
    5. 
              
  5. Place the file in the sample_dots/ directory to make it available in the template dropdown.
    6. 
            


            
Chat-Assisted Review Example

            
A small template that runs a codergen step, then opens an interactive chat so the user can refine the result before it is handed to an exit node:

            
digraph ChatReview {
    graph [
        goal="Draft content, then review it with a human-in-the-loop chat.",
        label="Chat Review",
        template="true",
        params="topic:text:required,
                mode:choice(interactive|autonomous):interactive"
    ]

    start [shape=Mdiamond, label="Start"]
    draft [handler="codergen",
        prompt="Write a short explainer on: $var.topic"]
    review [handler="interactive", mode="$var.mode",
        prompt="Refine the draft: $context.draft.output"]
    exit [shape=Msquare, label="Done"]

    start -> draft -> review -> exit
}

            
This template accepts a topic and lets the user choose between interactive review and autonomous mode.

          


          
          

            
Configuration


            
Config File Location

            
Needle stores configuration in ~/.needle/config.json with restricted file permissions (0600). The file is created automatically on first use.


            
Config Schema

            
{
  "schema_version": 1,
  "providers": {
    "openai":     { "api_key": "sk-...", "default_model": "gpt-4o" },
    "anthropic":  { "api_key": "sk-ant-...", "default_model": "claude-sonnet-4-6" },
    "gemini":     { "api_key": "AIza...", "default_model": "gemini-2.5-pro" },
    "tavily":     { "api_key": "tvly-..." }
  },
  "defaults": {
    "chat_agent": "claude",
    "chat_model": "claude-sonnet-4-6"
  },
  "server": {
    "port": 8080,
    "bind": "127.0.0.1",
    "auto_approve": false
  },
  "ui": {
    "theme": "dark"
  },
  "logging": {
    "level": "info"
  }
}


            
Environment Variable Precedence

            
Environment variables override config file values. They are never written to the file.

            

              
Env VarConfig Path

              
                
OPENAI_API_KEYproviders.openai.api_key

                
ANTHROPIC_API_KEYproviders.anthropic.api_key

                
GEMINI_API_KEYproviders.gemini.api_key

                
TAVILY_API_KEYproviders.tavily.api_key

              
            


            
CLI: needle config

            
Manage configuration from the command line using dot-notation paths:

            
# List all settings (API keys redacted)
needle config list

# Get a single value (raw, for scripting)
needle config get defaults.chat_model

# Set a value
needle config set providers.openai.api_key sk-xxx

# Remove a key
needle config unset providers.openai.api_key

# Print config file path
needle config path

# Open in your editor
needle config edit


            
UI Settings

            
The Settings view provides a graphical interface for all configuration. Changes are saved immediately to the config file. See Getting Started for a dashboard overview.

          


          
          

            
CLI Commands


            
needle run

            
Run a pipeline to completion in the terminal.

            
needle run <graph.dot> [options]

            
The pipeline executes synchronously. Human gates prompt in the terminal. Exit code reflects pipeline outcome.


            
needle serve

            
Start the HTTP server with the web dashboard.

            
needle serve [graph.dot] [options]

            
If no DOT file is provided, starts with an empty workspace. The Create view lets you build or load a pipeline interactively.


            
needle resume

            
Resume a pipeline from a checkpoint.

            
needle resume <checkpoint.json> [options]

            
Checkpoints are saved automatically in the .needle/ directory under the project. Resume picks up from the last completed node.


            
needle validate

            
Validate a DOT file without running it. Checks for structural issues: missing start/exit nodes, unreachable nodes, mismatched parallel/fan_in pairs, unknown handlers.

            
needle validate <graph.dot>


            
needle status

            
Show the status of runs managed by a running needle server.

            
needle status [--port PORT]


            
needle config

            
Manage configuration. See Configuration for full details.

            
needle config list
needle config get <key>
needle config set <key> <value>
needle config unset <key>
needle config path
needle config edit
